# Ozymandias Crossing — Account

## Purpose

Ozymandias Crossing is the first ordinary construction pressure on the Neptunian idea: can a model generate lightweight executable 3D geometry, inspect what it actually made in space, reason from that evidence, and correct it **inside the same model turn** without requiring a heavyweight Blender-style round trip or a human visual diagnosis?

The target loop is:

**semantic intent → relational construction → executable geometry → Observer perception → diagnosis → relationship-space correction → returned object**

The point is not to build a lightweight Blender. The point is to give the generator **proprioception**.

## What Ozymandias is

The first semantic desk-lamp attempt produced a spatially coherent articulated brass object that john, having forgotten the intended noun, independently read as an **elegant articulated brass spear fisher**.

That was accepted rather than corrected.

**Ozymandias, the Brass Spear Fisher** is now a named Workshop specimen and reusable compositional ancestor. The lamp is a descendant of Ozymandias rather than a replacement for him.

This established an important distinction:

**coherent geometry ≠ faithful semantic projection**

A generated object can be geometrically respectable while failing to preserve the intended identity strongly enough.

## Earned construction substrate

The crossing reuses existing machinery rather than creating a parallel modeling system:

- `WorkshopMats` for shared material vocabulary.
- semantic graph ancestry from `RelationalBuild`.
- endpoint-defined `workshopCyl(...)` members.
- ordinary `Betwixtable` spatial identity, focus, bounds, and tap behavior.
- Ozymandias' accepted articulated skeleton as named Workshop vocabulary.

The original relational chain was:

**base → lowerPivot → elbow → headPivot → shadeAxis → bulb**

with:

**supports → paired-arm → paired-arm → aims → contains**

The lamp descendant preserves the articulated ancestry while mutating the head toward a broad shallow reflector and preserving the successful bulb.

## Observer pressure

The early fixed 12-sense idea has been retired as an epistemic constraint. The Observer is now **unbounded but counted**: senses are telemetry, not a quota.

The first autonomous lamp-head policy uses 12 omnispherical poses × 7 aimed samples through the upper bounds, for **84 real runtime raycasts**. The number 84 is not privileged; it is simply the first policy's actual consumption.

The scan is executed by the browser's real Observer against the real runtime object. The resulting anonymous evidence transcript is retained at `deskLampBetwixtable.userData.neptunianHeadScan`. No lamp-head correction is made by that scan yet. Evidence first.

## Observer carrier

The previously speculative caretaker carrier has now earned an executable role.

A fireship-like Observer carrier is a Betwixtable presence in the compressed Jovian system, orbiting beyond Callisto with a slow wandering inclination. Its visible body is small; its Betwixtable shell provides a generous tap target.

For now its earned responsibilities are deliberately narrow: physically represent the Observer/report infrastructure, carry the current lamp-head mission/report, and expose the report to the human transport seam.

Tapping the carrier focuses it. Tapping again while focused downloads the current Observer report as JSON.

For the moment john shuttles that report back to the model. That human transport is explicitly temporary. A later crossing should attack the seam so runtime spatial evidence can return to the model within the same turn, possibly through machinery smaller than or outside Three.js.

## Current frontier

The immediate experiment is no longer “can we build a lamp?” It is:

**Can the model reason about the lamp head from Observer evidence, decide what spatial fact is wrong or weak, and improve the geometry without john supplying the diagnosis?**

Near-term next steps: shuttle the first carrier report back; reason from Observer evidence rather than source intention or human visual diagnosis; correct in relationship-space if supported; compare the second executable result; let failures earn richer probes; attack the runtime → model return seam; generalize dispatch only when a second real consumer earns it.
